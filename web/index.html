使用说明

引擎说明
基础流程
  1. 拖入游戏目录、游戏 exe、Steam 快捷方式或压缩包；工具会先解析真实目录，再进行引擎识别。
  2. 查看识别出的引擎和候选结果。普通用户保持“注入方式：自动”即可，管线会按引擎选择静态回填或运行时注入。
  3. 普通可回填引擎点击“开始翻译”。流程会依次执行提取文本、缓存命中、AI 翻译、校验、回填、生成启动器和写入诊断数据。
  4. KRKR、Unity / XUnity 和 Unity @ARCH000 只能点击“实时翻译”；点击“开始翻译”会弹出提示，不会进入静态流程。
  5. 完成后优先从“游戏库”启动；也可以进入游戏目录，运行管线生成的汉化启动器或原游戏 exe。
常用按钮和结果文件
开始翻译 完整流水线：提取、翻译、回填、部署启动器。适用于 BGI、RPG Maker、Ren'Py、Godot PCK、TyranoScript 等可静态回填的引擎。
实时翻译 KRKR 和 Unity 的唯一入口。KRKR 会启动原生 hook 与独立字幕窗口；Unity 会部署 XUnity / BepInEx 运行时翻译。
仅提取 只看文本覆盖率和引擎识别是否正确，不调用翻译 API，适合排查“为什么文本少”。
从 JSON 回填 复用已有译文文件重新写回游戏，适合修改术语、补翻、或重新打包。
游戏库 展示已经翻译过的游戏。点击卡牌启动汉化版，文件夹按钮只打开目录。
费用统计 每次任务会写入 _translation_meta/api_cache_stats.json，包含缓存命中、API 请求数和估算费用。
任务元数据 _translation_meta 保存启动器、诊断、缓存统计和引擎需要的运行文件，不建议手动删除。
引擎说明

BGI / Ethornell

Beta
适用
常见 BGI、Ethornell、Buriko 游戏，目录里通常有 .arc、BGI.gdb、sysprg.arc 或 system.arc。
流程
自动解包脚本、提取文本、DSC 重新压缩、静态回填，并生成原生汉化启动器。
启动
优先使用 启动汉化版.bat。已部署 sjis_ext.bin 和原生显示 hook，不再依赖 Python 或 Frida。

RPG Maker

稳定版
适用
MV、MZ、XP、VX、VXAce。常见特征是 www/data、Data、Game.rpgproject、.rvdata2 或 .rgss3a。
流程
提取事件、地图、公共事件、数据库文本；按版本选择 JSON、Marshal 数据或运行时替换路径。
注意
选项、对白、系统词会分类型处理。翻译后从游戏库启动即可，旧版 RGSS 游戏可能需要检查字体显示。

Ren'Py

稳定版
适用
目录里有 renpy、game、.rpy、.rpyc 或 .rpa 的视觉小说。
流程
自动处理脚本文本、菜单选项和翻译字符串；有 .rpa 时会尝试解包后再扫描。
注意
保留变量和方括号表达式，例如 [player]。若游戏已有多语言文件，可用 JSON 回填做二次修正。

Unity / XUnity

稳定版
适用
标准 Unity Mono 或 IL2CPP 游戏，常见特征是 *_Data、UnityPlayer.dll、GameAssembly.dll。
流程
只能点击“实时翻译”。工具会部署 BepInEx、XUnity.AutoTranslator、字体和翻译缓存，不直接破坏原资源。
启动
不要走“开始翻译”。从“实时翻译”、游戏库或原 exe 启动都会加载部署好的运行时翻译文件，首次启动可能需要等待插件初始化。

Unity @ARCH000 Lua VN

Beta
适用
部分 Unity 视觉小说使用 @ARCH000 一类 Lua 归档保存脚本文本。
流程
当前 GUI 统一归入 Unity 实时路线，只能点击“实时翻译”，由 XUnity 运行时捕获和替换显示文本。
注意
静态 Lua 归档回填保留为后续专用能力，不作为普通用户入口；若需要排查覆盖率，可先用“仅提取”。

Unity 资源直写

部分支持
适用
不适合 XUnity 的 Unity 游戏，或需要尝试直接处理 .assets 明文字符串的情况。
流程
资源直写保留为内部/实验路径；GUI 普通入口不再让 Unity 走“开始翻译”，避免低覆盖率静态替换误导用户。
注意
若目标是“能玩到中文”，优先点击“实时翻译”走 XUnity。只有明确需要研究资源结构时再看提取结果。

Godot PCK / Dialogic

Beta
适用
Godot 游戏的独立 .pck 或 exe 内嵌 PCK，尤其是使用 Dialogic .dtl 剧情脚本的游戏。
流程
解出 PCK，提取 .dtl、.tscn、.tres 等文本，回填后重建 PCK 或替换内嵌数据。
注意
会尽量保留事件 ID、标签、命令和控制符。若开场剧情丢失，优先检查 DTL 和事件 ID 是否保持原样。

Godot 加密 PCK

Beta
适用
普通 PCK 路线无法直接解包、文本需要运行时观察或 Frida 辅助的 Godot 游戏。
流程
通过运行时 hook 和已有翻译缓存替换显示文本，必要时复用 Godot PCK 的 DTL/资源补丁逻辑。
注意
自动模式会优先选择更稳的静态 PCK 路线；只有检测到加密或静态不可行时才走运行时方案。

Godot 明文工程

部分支持
适用
目录里直接存在 .gd、.tscn、.tres、.translation 等明文资源的 Godot 游戏。
流程
扫描常见文本字段、按钮文本、标签文本和资源描述，能安全回填的内容会写回。
注意
如果游戏实际封在 PCK 里，应由 Godot PCK 引擎处理；明文工程路径主要用于已解包或开发版目录。

GameMaker / YoYo

部分支持
适用
有 data.win 的 GameMaker 游戏，例如部分 YoYo 引擎独立游戏。
流程
从 STRG 字符串表和主程序数据段提取文本；能放回原槽位的译文会安全回填。
注意
超长中文可能被跳过，覆盖率不一定完整。像素字体、字号和可读性通常需要单独检查。

TyranoScript / TyranoBuilder

实验性
适用
目录里有 data/scenario、package.json 和 tyrano/plugins/kag，或这些资源被封装在 NW.js 游戏 exe 内。
流程
点击“开始翻译”。工具会结构化提取 .ks 可见文本，使用当前翻译器处理，再精确写回松散脚本或 exe 内嵌 ZIP。
安全
脚本标签、资源路径、变量和动态金额表达式不会送去翻译；内嵌 exe 会先集中备份，回填后重新打开 ZIP 逐条校验。
注意
目前只完成一个真实游戏样本，仍属实验支持。若游戏启动或文本显示异常，请先“卸载汉化”恢复原文件，并保留 _translation_meta 诊断数据。

吉里吉里 / KiriKiri

Beta 版
默认流程
只能点击“实时翻译”。工具按 LunaTranslator 思路走原生 hook，捕获 KAGParser 等显示文本，并在独立字幕窗口显示中文。
显示方式
人名和正文分通道处理；已有译文优先读本地映射，新文本可实时补译，并写入 _translation_meta 供后续复用。
启动
GUI 实时翻译会直接拉起 native runtime 和字幕窗口，不再经过 bat / PowerShell。目录里的 启动汉化版.bat 只是便携备用入口。
静态脚本
.ks、.tjs、普通 XP3 / SCN 的提取能力保留为辅助诊断和后续补翻基础，不再作为 KRKR 默认翻译入口。

Unreal Engine

部分支持
适用
有 .pak、.utoc、.ucas、Content 或 .uproject 的 Unreal 游戏。
流程
优先扫描已解包或明文本地化资源；如果配置了 UnrealPak，会尝试解包部分 .pak。
注意
IoStore 和大多数 .uasset 二进制回填尚未自动化，通常需要 FModel、UnrealPak 或 UE 专用流程配合。

WOLF RPG Editor

测试版
适用
Wolf RPG Editor 游戏，常见特征是 Data.wolf、Game.dat 等资源。
流程
使用 UberWolf 自动识别密钥并解包，结构化提取地图、公共事件和数据库文本，翻译后重新打包。
覆盖
支持普通目录、标准 WOLF 归档及 UberWolf 可识别的 Pro 保护，不依赖运行时实时翻译。
注意
当前为测试版；自定义归档和依赖名称匹配的脚本仍需实际游戏流程验收。

通用文本扫描

兜底
适用
没有匹配到专用引擎，但目录里有 .txt、.json、.csv、.xml、.ini、.lua 等明文文件。
流程
只扫描明文资源，过滤配置键和明显不是玩家可见文本的内容。
注意
如果某个封包游戏落到这里，通常说明专用引擎未识别或资源被加密；文本条数很少时不要急着翻译，先检查识别结果。

设置

本地模型只使用本页参数；云端每批条数、云端并发数和 API 设置不会参与本地推理。

两个模型可同时保留，切换不会删除另一个模型。模型和运行器从腾讯 ModelScope 与 llama.cpp 官方源下载，不计入安装包；翻译完全在本机运行，不消耗试用额度。
开启缓存会更便宜；翻译的游戏越多，跨游戏常见文本、人名、选项和 UI 命中越多，长期越省钱。
自动清理只删除最旧的全局译文缓存，不会删除游戏目录、汉化文件或每个游戏的元数据。
这些设置作用于 KRKR 原生显示层 hook 的独立字幕窗口；字号、颜色、宽高、跟随与锁定会应用到当前窗口，字幕纯文本模式切换下次启动生效。
界面语言用于后续多语言 UI；默认目标语言会同步到翻译任务。
